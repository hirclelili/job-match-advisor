# 匹配度诊断标准

> 供 SKILL.md Step 5 调用。对每条 JD 要求做四档诊断，严禁美化档位。

---

## 核心原则：诚实 > 讨好

Claude 有天然的讨好倾向，会倾向于把 🔴 标为 🟠、把 🟠 标为 🟡，让用户感觉良好。**这是最大的风险**。

**为什么诚实更重要**：
- 用户拿着"美化过的诊断"去面试，遭遇真实追问时会暴露
- 提前知道 🔴 才能提前准备应对策略
- 假装 🟡/🟠 的用户进了面试反而更容易出丑

**判断原则**：宁可标低一档，也不标高一档。

---

## 四档诊断判定标准

### 🟢 直接命中

**判定条件（同时满足）**：
1. 用户经历中**明确**包含该技能或经历
2. 有**具体的数据或案例**作为支撑
3. 用现有简历表达基本能体现出来

**示例**：JD 要求"熟练使用 SQL"，用户简历写"用 SQL 提取 DAU 数据并做留存分析"→ 🟢

**行动建议**：准备 1 个具体案例故事，面试时直接讲，无需改写简历。

---

### 🟡 需重新包装

**判定条件**：
1. 用户经历里**确实做过**相关的事
2. 但当前简历的**表达方式**没有体现出来，或者讲的角度不对
3. 换一个视角或表达，这条要求是完全能覆盖的

**典型情形**：
- 用户做了用户访谈，但简历写的是"参与用户调研"而非"独立设计访谈方案"
- 用户协调了多个部门推进项目，但简历没有体现"跨部门推动"
- 用户用过 A/B 测试，但简历只写了结论没写实验设计过程

**行动建议**：在应答策略里明确告诉用户"如何重新表达这段经历"，提供具体改写示例。

---

### 🟠 部分覆盖

**判定条件**：
1. 用户经历里有**相关但不完全对应**的内容
2. 勉强能讲，但力度明显不足
3. 面试官如果追问会露底

**典型情形**：
- JD 要求"独立完成用户调研方案设计"，用户只做过"跟着 mentor 做过几次访谈"
- JD 要求"有活动策划全流程经验"，用户只参与过活动执行（没有立项/复盘）
- JD 要求"有 B 端产品经验"，用户只做过 C 端但理解过 B 端产品

**行动建议**：
1. 告诉用户"可以讲，但要提前承认局限性"
2. 提供"部分覆盖类问题"的应答框架：先说自己做了什么，再说和 JD 要求的差距，再说如何弥补

---

### 🔴 真 gap

**判定条件**：
1. 用户经历里**完全找不到**相关内容
2. 即使换角度包装也无法覆盖

**典型情形**：
- JD 要求"有 SQL 经验"，用户从来没用过 SQL
- JD 要求"有独立带项目/团队经验"，用户只有执行经历
- JD 要求"有特定行业经验（如医疗/金融）"，用户完全没有

**注意**：🔴 不等于"这个岗位不能投"。真 gap 分两种：
- **可弥补型**：技能类 gap，可以面试前突击学习；或者该项是隐含/加分项
- **难弥补型**：经验类 gap，需要时间积累，面试中只能坦诚应对

**行动建议**：
- 明确告诉用户这是真 gap，不要假装没看见
- 给出"真 gap 面试应对模板"（见下节）

---

## 🟡 vs 🟠 边界判断（最容易混淆的地方）

**判断核心问题**："用户做过这件事吗？"

- 做过，只是表达没到位 → 🟡（换个说法就能对上）
- 做过，但规模/深度不达标 → 🟠（能讲但不够强）
- 没做过，只是相关行业/方向 → 🔴（不能硬撑）

**案例对比**：

| 情境 | 正确档位 | 错误档位 |
|------|---------|---------|
| 用户做过用户调研但没写在简历里 | 🟡 | ❌🟠 |
| 用户协助做过活动但没独立负责 | 🟠 | ❌🟡 |
| 用户了解 SQL 但从未实际使用 | 🔴 | ❌🟠 |
| 用户做过小规模数据分析但要求是大型分析项目 | 🟠 | ❌🟢 |

---

## 真 gap（🔴）面试应对模板

面试中被问到真 gap 领域，推荐以下三步应对：

**步骤 1：坦诚承认**
> "这方面我目前还没有直接经验..."

**步骤 2：展示学习意愿 + 最近行动**
> "...但我最近已经开始 [具体行动，如：在学 SQL，已做完基础课程；或：研究了 3 家同类产品的功能设计]..."

**步骤 3：用相关经历降低风险**
> "...我有 [相关但不完全对应的经历]，这让我相信在 [时间范围] 内能较快上手..."

**注意**：这套模板只适合真正有弥补意愿和行动的情况。如果用户完全没有任何相关基础，应如实告知"这个 gap 较大，建议面试前评估一下这个岗位是否合适"。

## 五组诊断示例

### 示例 1：🟢 直接命中

**JD 要求**：熟练使用 SQL 进行数据分析

**用户简历**：在字节跳动实习期间，用 SQL 从数据仓库提取用户行为数据，完成用户留存漏斗分析，支撑 2 个产品决策。

**诊断**：🟢 直接命中
- 匹配点：有具体的 SQL 使用场景（用户行为数据提取）、有分析产出（留存漏斗）、有业务影响（支撑产品决策）
- 行动建议：面试时准备 1 个具体的 SQL 场景（如"当时遇到的最复杂的查询是什么"），不需要改写简历

---

### 示例 2：🟡 需重新包装

**JD 要求**：能独立设计用户调研方案

**用户简历**：在实习中做了用户访谈，收集了用户反馈。

**诊断**：🟡 需重新包装
- 现状：确实做过用户调研，但简历表述停留在"做了访谈"层面，没体现"独立设计方案"
- 建议重新包装：改为"独立制定访谈大纲（覆盖 5 个核心场景），招募 12 名目标用户完成深访，产出调研报告推动 X 产品决策"
- 面试准备：能回答"你是怎么设计这次调研的""为什么选这些受访者"等追问

---

### 示例 3：🟠 部分覆盖

**JD 要求**：有活动策划全流程经验（立项→执行→复盘）

**用户简历**：参与了公司双十一活动的执行，负责文案撰写和用户群推送。

**诊断**：🟠 部分覆盖
- 部分匹配：做过活动执行，有文案和推送经验
- 不足：没有独立立项（需求来源）和复盘（数据分析 + 结论沉淀）的经历
- 面试建议：可以讲，但要补充"了解活动策划全流程，当时在执行阶段，对立项逻辑有理解"；或提一个你复盘过的小型活动（哪怕规模很小）

---

### 示例 4：🔴 真 gap（可弥补型）

**JD 要求**：有 Python 数据处理基础

**用户简历**：无任何 Python 相关经历

**诊断**：🔴 真 gap（可弥补型）
- 说明：Python 基础属于技能类 gap，有学习曲线但短期内可以达到基本水平
- 面试前建议：如果距面试还有 1 周以上，优先完成 Python 数据处理基础课（pandas/numpy 基本操作）
- 面试应对：坦诚说"Python 方面我目前还在学习中，已经完成了基础课程，能做基本的数据处理，复杂的项目场景还需要进一步练习"

---

### 示例 5：🔴 真 gap（难弥补型）

**JD 要求**：有独立带项目/管理团队经验

**用户简历**：所有经历均为执行角色，从未带过项目或团队

**诊断**：🔴 真 gap（难弥补型）
- 说明：管理经验类 gap 是经历积累问题，不是短期学习能补的
- 建议：
  1. 投递前评估：如果岗位明确要求管理经验且是必须项，建议谨慎投递
  2. 如果决定投递：面试中坦诚说"还没有带团队的机会，但在 [XX 经历] 里我有协调推动经历"，以软技能来部分对标
  3. 不要假装有管理经验——追问会立刻露馅
